# opencode TUI 汉化插件 设计文档

- 日期：2026-10-07
- 状态：待评审
- 关联：现有二进制汉化方案见 `~/opencode-zh/README.md`；可行性探针见 `~/opencode-zh/plugin-probe/`

## 1. 背景与目标

目前本机 opencode v2.0.24 的 TUI 汉化是通过"二进制补丁"实现的：翻译写进 ELF `.bun` 段的模块图，并清零字节码指针。该方案覆盖完整，但每次升级都要重打补丁，且不便分享。

已通过探针验证：TUI 插件可以在运行时拦截 OpenTUI 的文本渲染，并按词典翻译界面文字。本项目的目标是把这个能力做成一个正式插件：

- 不改二进制，opencode 升级后基本不受影响
- 复用现有 1528 条译文，全量覆盖 TUI 文案
- 简体中文界面；命令名、快捷键、文件名等技术标识保持英文
- 安装简单，可维护、可分享

## 2. 范围

### 覆盖

- 全量 TUI 界面文案：主界面、命令面板、设置、对话框、会话界面、mini 界面、崩溃界面等
- 输入框占位符（placeholder）
- 巡检发现的其它文本渲染路径

### 不覆盖

- 服务端返回的动态内容（模型输出、工具输出、报错原文）
- 发送给模型的系统提示词
- 命令名、快捷键、代码、文件名、模型/代理名称
- provider 自动重试补丁（属于服务端行为补丁，插件无法实现，继续由二进制补丁承担）

## 3. 架构与组件

源码目录：`~/opencode-zh/plugin/`

```text
plugin/
  package.json      # name、type: module、exports: { "./tui": "./tui.ts" }
  tui.ts            # 插件主体
  dict.json         # 运行时词典
  audit.mjs         # 审计脚本：统计巡检期间未命中的英文渲染文本
  install.sh        # 安装脚本（可选）
  README.md
```

### 3.1 插件主体（tui.ts）

启动时（`setup(context)`）：

1. 读取 `dict.json` 与可选的用户覆盖词典 `~/.config/opencode/zh-hans-overrides.json`
2. 注册 hook：
   - `TextBuffer.setStyledText`：遍历 `styled.chunks`，对每个 chunk 的 `text` 做精确匹配替换（主路径）
   - `InputRenderable.placeholder` / `TextareaRenderable.placeholder`：替换访问器 setter
   - 巡检后按需补充其它 hook
3. 自检：每个 hook 注册失败只记录日志，不抛异常、不影响 TUI 启动
4. 审计模式（插件 options 开启）：把未命中的英文 chunk 文本追加到 `/tmp/zh-hans-audit.log`（去重）

设计约束：

- 只做**精确匹配**，不做模糊/分词替换，避免误翻动态内容
- 词典查找使用 `Map`，单次匹配 O(1)，对渲染性能影响可忽略
- 不修改 OpenTUI 的其它行为；hook 内部异常一律捕获并降级为原逻辑

### 3.2 词典（dict.json）

- 由现有 `~/opencode-zh/dict/zh-CN.json` 转换生成：取 `modules` 中所有 原文→译文 映射，合并去重
- 运行时词典的键是**实际渲染文本/片段**；与源码字面量大多一致，差异通过审计巡检补齐
- 格式：

```json
{
  "version": 1,
  "entries": {
    "Settings": "设置",
    "Commands": "命令"
  }
}
```

- 用户覆盖：`~/.config/opencode/zh-hans-overrides.json`（同格式），加载时覆盖内置词典，便于个人改词

### 3.3 审计与巡检

- `audit.mjs`：tmux 自动巡检脚本，依次打开首页、命令面板、设置、模型选择、会话列表、会话视图、帮助等界面并截图
- 巡检时开启插件审计模式，收集未命中的英文渲染文本
- 人工筛出真正的界面文案，补充进 `dict.json`，重复 1-2 轮直到覆盖率达标

## 4. 安装与启用

开发期（改动即生效）：

- `~/.config/opencode/cli.json` 增加：`"plugins": [{ "package": "/home/xlht/opencode-zh/plugin" }]`

稳定后（推荐）：

- 复制到 `~/.config/opencode/plugins/zh-hans/`（自动发现，无需改配置）
- 备选：保留 cli.json 绝对路径注册（适合持续开发）

卸载：移除 cli.json 条目或插件目录即可，无副作用。

## 5. 错误处理与兼容性

- OpenTUI 内部 API（`setStyledText` 的 chunk 形状、placeholder 访问器）是**非公开接口**，大版本升级可能变化
- 插件启动时逐项自检并打印/记录结果；hook 失效时插件静默降级（界面回到英文），不崩溃
- 插件内所有 hook 用 try/catch 包裹，任何异常不影响 TUI 主流程

## 6. 测试与验收标准

- **功能**：首页、命令面板、设置、模型选择、会话列表/会话视图、mini 界面均为中文（技术标识除外）
- **回归**：命令名、快捷键、文件路径、模型名、代码、动态内容不被误翻
- **审计**：巡检后未命中的英文界面文案 ≤ 少量已知项（逐项记录原因）
- **稳定性**：插件加载失败/API 变化时不崩溃；TUI 启动时间无明显变化
- **对照**：与现有二进制汉化版的界面截图对照，覆盖率不低于二进制版

## 7. 与二进制补丁的关系

- 开发与验证期间两者并存，互不影响
- 插件验收通过后，由用户决定是否恢复原版二进制；provider 自动重试补丁如需保留，可单独构建一个只含该补丁的二进制（构建方式在实施阶段补充到 README）

## 8. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| OpenTUI 内部 API 变化导致 hook 失效 | 自检 + 静默降级；升级后跑一次巡检即可定位 |
| 词典与运行时文本不一致导致漏翻 | 审计模式 + 巡检迭代 |
| 精确匹配误翻动态内容 | 词典只收录界面文案；发生概率极低 |
| 插件影响渲染性能 | Map 精确匹配，实测无感；如异常可通过 options 关闭 |

## 9. 非目标（YAGNI）

- 不做多语言框架（只做简体中文）
- 不做图形界面配置
- 不做自动翻译/词典生成服务
- 不发布到 npm（先本机使用，结构保持可分享）
